# 2026-05-07

## Naja 市场值班官

- 老板希望 Naja 成为每次启动后持续学习、记住市场/新闻、调整策略认知并主动汇报的系统。
- 决定不新增页面，把能力呈现在现有 `/awakening` 觉醒页面。
- 新增应用层 `MarketCopilot`，汇总天时、地利、人和、叙事、热点和策略调整建议。
- 新增 `/api/naja/ask`、`/api/naja/digest`、`/api/naja/digest/send`，支持直接问 Naja 和发送汇报。
- 新增统一通知适配器，支持 DingTalk 和手机/iMessage；外部发送 API 需要 `confirm=true`。
- 新增 repo 内技能 `deva/naja/skills/naja-api`，用于以后通过本地 Naja API 直接提问。

## Naja Agent 化

- 老板希望弱化 Web 能力，强化 skill 和对话能力。
- 新增 `application/naja_agent.py`，作为 Naja 的对话/技能门面：`ask`、`digest`、`send_digest`、`capabilities`。
- 新增 `/api/naja/agent` 和 `/api/naja/skill`，Web/API 只作为本地传输，主接口定义为 `skill/dialogue`。
- 觉醒页移除直接问答和发送按钮，保留市场值班官状态镜像。
- 更新 `deva/naja/skills/naja-api`：支持 `ask`、`digest`、`send --confirm`、`capabilities` 命令。
- 老板要求 Naja API 技能使用方法要在 WebUI 觉醒页体现；已在觉醒页 Agent 状态区加使用方法卡片，展示 skill 脚本命令和 `/api/naja/agent`、`/api/naja/skill` 端点。
- 老板进一步明确要强化“整个系统 API 端点 + 对应技能”。已新增 `application/api_catalog.py`，把 system/market/radar/cognition/knowledge/strategy/attention/events/config/agent 等 52 个 API 端点做成能力目录；`NajaAgent` 新增 `api_catalog` skill；Web API 新增 `/api/naja/api-catalog`；`naja-api` skill 脚本新增 `endpoints` 和 `--group`。
