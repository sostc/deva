# 在利润跃迁被市场发现之前：我用 Python 搭了一台"结构性增长雷达"

> 多数投资者看的是"增长"，但真正的领先信号是"增长是否在加速"。
> 这篇文章讲我怎么用纯 Python 搭了一套系统，去捕捉产业从周期性波动转向结构性上升的拐点。

---

## 一、问题的起点

做投资久了，你会发现一个规律：**市场对"结构性变化"的定价总是慢半拍。**

不是市场不聪明，而是结构性变化的发生过程太微妙了。当一家公司的利润率从"周期性波动"转向"趋势性上升"时，最初的样子和普通周期反弹几乎一模一样——营收在涨，利润在涨，看起来只是又一个好年景。

等到所有人都意识到"这次不一样"的时候，估值已经涨完了。

所以核心问题不是"这家公司好不好"，而是：

> **这个行业的利润改善，是周期性的反弹，还是结构性的跃迁？**

如果是周期性反弹，利润会回去；如果是结构性跃迁，利润率站上新台阶就不回来了。两者的早期信号几乎相同，但含义天差地别。

---

## 二、核心思路：二阶导 > 一阶导

借一点物理学的直觉：**位置的一阶导数是速度，二阶导数是加速度。**

投资中：
- 一阶导 = 增长率本身（营收涨了 20%）
- 二阶导 = 增速的变化率（去年涨 15%，今年涨 20%，增速在加速）

多数人盯一阶导——"增长 20% 不错"。但真正领先的信号在二阶导——"增速从 15% 加速到 20%，拐点正在形成"。

**增速在加速，比增速本身重要。**

这就是"结构性增长雷达"的设计原点：不预测业绩数字，而是追踪六维度产业数据的二阶导信号，在利润跃迁的早期拐点发出预警。

---

## 三、六维度产业状态卡

要判断一个产业是否正在发生结构性变化，不能只看一两个指标。我设计了六个维度的追踪体系：

| 维度 | 含义 | 数据来源 |
|------|------|---------|
| **需求** demand | 营收同比增速 | 财报数据 |
| **供给** supply | 资本开支 / 产能 | 财报 + 新闻 |
| **库存** inventory | 库存周转天数 | 新闻 + 研报 |
| **价格** price | 产品价格 / 价差 | 行情 + 新闻 |
| **利润** profit | 毛利率 / 净利率 | 财报数据 |
| **现金流** cashflow | 经营现金流 / 营收 | 财报数据 |

每个维度不是只看当前值，而是追踪历史序列，自动计算：
- **一阶导**（增速）
- **二阶导**（增速的变化率，即加速度）

当多个维度的二阶导同时出现异常——比如需求加速 + 毛利率改善加速 + 现金流转化率转正——产业可能正在发生结构性变化。

---

## 四、S0→S4：五阶段估值状态机

发现信号只是第一步。一个产业从"普通周期"到"估值重估候选"，要经过五个阶段的逐步验证。我把它设计成一个状态机：

```
S0 普通周期 → S1 需求加速 → S2 瓶颈形成 → S3 利润兑现 → S4 重估候选
```

每个阶段推进到下一阶段，都需要满足明确的条件：

**S0 → S1：需求加速**
- 触发条件：需求增速的加速度 ≥ 5 个百分点
- 含义：行业不再只是"在增长"，而是"增长在加速"

**S1 → S2：瓶颈验证**
- 触发条件：供给瓶颈假设被验证（不是产能跟不上，而是存在结构性壁垒）
- 含义：供需缺口开始形成，议价权正在转移到供给方

**S2 → S3：利润 + 现金流双确认**
- 触发条件：利润率扩张假设 + 现金流拐点假设同时被验证
- 含义：不仅毛利在改善，而且现金流真的在跟上——利润是真的，不是纸面上的

**S3 → S4：预期差为正**
- 触发条件：结构性增长潜力 − 市场隐含增长 > 3 个百分点
- 含义：市场尚未充分定价这种结构性变化，存在重新估值的窗口

**回退机制**：如果需求减速超过 2 个百分点，状态回退。这不是一条单行道。

为什么要设计成状态机？因为**结构性变化是一个过程，不是一个事件**。你不能因为一个季度的数据好就下结论，需要在时间维度上逐步积累证据。

---

## 五、三 Agent 验证链：防止确认偏见

这是整个系统我最得意的部分。

人做投资研究最大的敌人是**确认偏见**——一旦你倾向于相信某个结论，就会不断寻找支持它的证据，忽略反面信号。

所以我没有用一个"全知全能"的模型一步到位，而是拆成三个角色，互相制衡：

### ① 发现者 Discovery Agent

**职责**：扫描六维度的二阶导信号，当检测到异常时，提出候选假设。

它有 6 条规则引擎，比如：
- 需求增速显著加速 → 提出"需求激增"假设
- 需求加速但供给未跟上 → 提出"供给瓶颈"假设
- 毛利率改善加速超过阈值 → 提出"利润率扩张"假设
- 多条同时成立 → 提出"利润跃迁"综合假设

关键设计：**发现者只负责"提出"，不负责"下结论"**。每个假设带一个初始置信度，但这个置信度只是起点。

### ② 验证者 Verification Agent

**职责**：对每个假设做跨因子一致性检验，**主动寻找反证**。

验证者的判决有四档：
- **确认**：支持证据占优且跨因子一致
- **部分支持**：有支持但反证也存在
- **不足**：证据不够，无法判断
- **否决**：强反证或跨因子矛盾

**关键设计：验证者有否决权。**

如果发现者说"需求在加速"，但验证者发现供给也在加速（产能大规模扩张），或者现金流没有跟上（利润可能是纸面上的），验证者可以直接否决这个假设。

被否决的假设不会进入下一阶段的状态机评估。这就是防止确认偏见的核心机制——**提出假设的人和检验假设的人不是同一个"大脑"**。

### ③ 估值者 Valuation Agent

**职责**：基于验证结果，构建三种估值情景，计算预期差。

三种情景：
1. **周期回归**：假设 60% 的利润改善会回吐（均值回归）
2. **基准**：当前趋势延续
3. **结构性增长**：利润率站上新台阶，不回吐

预期差的计算逻辑：

```
预期差 = 结构性增长情景下的隐含增长率 − 市场当前定价隐含的增长率
```

- 预期差 > 0：市场低估了增长潜力，存在重估空间
- 预期差 < 0：市场已经充分甚至过度定价

**正预期差是 S3 → S4 的必要条件。** 只有当系统判断"市场尚未充分定价"时，行业才会进入"重估候选"状态。

## 六、数据流：从个股到产业

系统当前接入三类数据源：

**财报数据**（东方财富 API）
- 营收、归母净利、毛利率、经营性现金流及同比增速
- 按市值加权聚合到行业维度：个股财报 → 行业基本面

**行情数据**（FundamentalDataFetcher）
- 股价、PE、PB、市值
- 用于加权计算和估值情景

**新闻事件**（TextFocusedEvent 订阅）
- 系统注意力引擎过滤后的高信号新闻
- 自动匹配产业关键词，按情感倾向生成支持/反证证据
- 比如"HBM 价格上涨"会作为 HBM 行业的支持证据
- "竞争者大规模扩产"会作为反证证据

数据的流动路径：

```
个股财报/行情 → 市值加权聚合 → 行业基本面 → 六维度状态卡
                                        ↓
新闻事件 → 关键词匹配 → 证据链（支持/反证）↘
                                        ↓
                               发现者 → 验证者 → 估值者
                                        ↓
                               状态机评估 S0→S4
```

---

## 七、运行频率与使用方式

系统每小时自动运行一次全链路：
1. 拉取最新财报和行情数据
2. 按市值加权聚合到行业维度
3. 喂入六维度状态卡
4. 运行三 Agent 验证链
5. 评估状态机推进
6. 输出当前阶段分布和预期差

每次运行后，可以在 Web 面板看到：
- 每个行业当前处于 S0-S4 的哪个阶段
- 六维度数据覆盖情况（绿灯=有数据，灰灯=无数据）
- 支持证据数 vs 反证数
- 预期差（正=市场低估，负=市场已定价）

**系统的核心输出不是"买什么"，而是"哪些行业值得深入研究"。** S4 候选意味着系统判断该行业可能正在发生结构性变化且市场尚未充分定价——这时候需要人工去做深度尽调，系统帮你缩小了搜索范围。

## 八、几个关键的设计选择

**1. 为什么用纯 Python，不接 LLM？**

LLM 擅长理解和生成文本，但不擅长严格的逻辑推理。状态机的转换规则、验证者的否决逻辑、预期差的计算公式——这些需要的是确定性和可审计性，不是创造性。

每一step的逻辑都可以追溯：为什么 S2 推进到 S3 了？因为利润率扩张假设和现金流拐点假设同时被验证。为什么假设被验证了？因为有 3 条支持证据，0 条反证，跨因子一致性通过。

LLM 适合做数据采集和新闻解读的辅助，但核心推理链必须是规则引擎。

**2. 为什么不用一个综合评分，而要用状态机？**

综合评分的问题在于"不可解释"。一个行业得分 85 分，然后呢？85 分意味着什么？需要做什么？

状态机的好处是**每个阶段有明确的含义和行动指向**：
- S0/S1：观察期，不急
- S2：重点关注，瓶颈是否会被验证
- S3：利润已经兑现，看市场是否定价了
- S4：预期差为正，值得深度研究

**3. 为什么验证者要有否决权？**

因为投资中最大的风险不是"没发现机会"，而是"把非机会当成了机会"。否决权是一道刹车——当反面信号足够强时，直接否决，不进入下一步。

这道刹车在回测中避免了多次"假突破"——产业数据短期改善但随后回落的情况。

## 九、局限与展望

**当前局限：**
- 库存和产能维度主要靠新闻证据，缺少量化数据源
- 只覆盖了 A 股，港股和美股尚未接入
- 预期差的计算依赖 PE 作为市场定价的代理变量，有简化

**后续方向：**
- 接入产业链上下游价格数据（如 HBM 现货价、锂价）
- 扩展到港股和美股市场
- 加入历史回测框架，验证 S4 候选的实际收益率
- 探索用 LLM 做新闻深度解读（但不参与核心推理链）

---

## 十、总结

结构性增长雷达的核心哲学：

1. **不预测业绩数字，识别结构性变化**——前者是分析师的工作，后者才是 alpha 来源
2. **二阶导 > 一阶导**——增速的加速度比增速本身更领先
3. **验证者有否决权**——防止确认偏见是投资系统的第一要务
4. **预期差驱动**——只有市场尚未充分定价的机会，才是真正的机会
5. **状态机而非评分**——每个阶段有明确含义和行动指向

这套系统不是要替代人的判断，而是**用机器的勤奋和纪律，缩小人的搜索范围**。

机器负责每天扫描所有行业的六维度信号、跑三 Agent 验证链、维护状态机推进。人负责在 S4 候选出现时，去做机器做不了的事：和管理层聊、看工厂、理解竞争格局。

**人机协作，而不是人机替代。**
