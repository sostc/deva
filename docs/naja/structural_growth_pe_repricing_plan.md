## 1. Part 1：PE 定位区间 + 周期/成长分类

### 1.1 Step 0（前置，必须先做）：换掉硬编码 PE

**改动**：`deva/naja/bandit/fundamental_data_fetcher.py::_enrich_us_fundamental`

- **删除** `us_fundamentals` 常量字典（PE、市值全部删掉）。
- 美股改走东方财富 `push2`：`secid=105.<CODE>`（纳指）/ `106.<CODE>`（纽指）/ `107.<CODE>`（美粉），字段与现有 A 股实现**同构**（`f9`=PE动态、`f162`/`f163`=PE静/TTM、`f23`/`f164`=PB、`f116`=总市值）。
  - 选它的理由：A 股已经在用同一套字段解析，改动量最小；不需要新增依赖；本机不需要 OpenD 在跑。
- 保留 `Market.US` 判定与新浪**价格**通道（价格的实时性比 PE 重要），只把 PE/PB/市值换成东财。
- ❗**拿不到就是拿不到**：沿用 `source` / `missing` 语义，**绝不再用任何常量兜底**。取不到 → `pe_ratio = None`（不是 0.0）+ `pe_missing = "eastmoney: 无此标的数据"`，UI 写「未采集（源+原因）」。
  - ⚠️ 这里有个量纲陷阱要一起处理：**A 股 `eps` 是年初至今累计口径，美股是单季/全年**（`StockFinancial.report_type` 已区分）。算 PE 必须按 `report_type` 年化，否则差 4 倍。

### 1.2 Step 1：新增 `pe_classifier.py` —— 分类不靠拍脑袋

新模块放在领域层 `deva/naja/structural_growth/pe_classifier.py`（纯函数，好测）。

输出 `ValuationRegime`：

| 分类 | 判据（三条里至少两条命中） | 含义 |
|---|---|---|
| `CYCLICAL` 周期 | ① 近 8 期净利同比**标准差 > 阈值** 或出现过负增长期；② 毛利率跟随价格维度同步摆动（相关性 > 0.5）；③ 自身 PE 历史长期低中枢 | 利润均值回归，**不配成长估值** |
| `STRUCTURAL_GROWTH` 结构性成长 | ① 连续 N 期净利同比为正**且加速度为正**；② 毛利率单调扩张；③ 经营现金流/净利 ≥ 0.8（利润质量，防纸面利润） | 利润跃迁可持续，可切换成长估值 |
| `BASE` 稳态 | 介于两者之间 | 趋势延续 |
| `UNKNOWN` | 数据点 < 4 期或关键字段缺失 | ❗**必须显式存在**，`None ≠ BASE` |

> ❗分类输出必须带 `confidence` + `evidence[]`（哪几条命中、具体数值），**不许只给一个标签**。理由同 `PanicAnalyzer`：只给结论不给依据，后面没人能复核。
> ❗不许默认 `BASE` —— 数据不足必须返回 `UNKNOWN`，否则「没数据」会被静默读成「稳态」，这正是本项目反复踩的坑。

### 1.3 Step 2：PE 区间定位（双层基准，缺一不可）

- **自身历史分位**：`PE_t = P_t / EPS_TTM`，用已有日 K（富途 `request_history_kline`，注意 10.x 返回 3 元组且必须同时给 `start`/`end`）× 财报缓存里的 TTM EPS 自算。窗口默认 3 年。
- **同业横截面分位**：复用 `industry_aggregator` 已有成分股列表做 PE 排序。
- 页面呈现（一行）：
  `PE 32.4（TTM，源：东财）｜自身 3 年分位 68%｜同业分位 45%｜分类：结构性成长（中置信，2/3 条命中）`

### 1.4 Step 3：目标 PE 区间 —— 重定价的"尺子"

把 `valuation_agent` 的三情景从"只假设利润率"升级为"**PE 带 × EPS**"双变量，每个情景给 `[pe_low, pe_high]`：

| 情景 | PE 带来源 |
|---|---|
| 周期 | 该股**自身历史 PE 分布的低分位段** + 同业 `CYCLICAL` 类票的 PE 分布 |
| 基准 | 自身 PE 中位数附近 |
| 结构性 | 同业 `STRUCTURAL_GROWTH` 类票的 PE 分布上段 |

> ❗**PE 带不许写死成常量表**。应由"同类票实测分布 + 自身历史分布"动态生成；只有在样本不足时才用兜底常量表，且必须在 UI 上标注「来自兜底表，非实测」。
> 理由（本项目的实锤教训）：OpenRouter 那套写死周期粒度的代码改版后**静默失效 160 天**。写死的估值带同样会。

## 2. Part 2：结构性行情来了吗 / price in 了吗 / 还有没有买点

### 2.1 核心新增指标一：`priced_in_ratio`（市场已经定价了多少）

```
priced_in_ratio = (PE_now − PE_cyclical_mid) / (PE_structural_mid − PE_cyclical_mid)
```

| 区间 | 判读 |
|---|---|
| < 0.3 | 市场仍按**周期**定价 → 认知差最大，但也可能市场是对的 |
| 0.3 ~ 0.7 | 部分 price in |
| > 0.7 | 基本 price in，剩下的**只能靠业绩兑现**，不是靠重估 |

> ❗**必须和分类交叉读，这是这块设计的灵魂**：
> - 周期股 + `priced_in_ratio` 高 → **不是机会，是陷阱**（它的尺子本来就是周期带，冲进结构性带叫泡沫）
> - 成长股 + `priced_in_ratio` 低 → **才是机会**（基本面已变，市场还没换尺子）
> - 现在的代码完全没有这个交叉，所以"预期差 +5%"到底是机会还是陷阱，答不了。

### 2.2 核心新增指标二：`asymmetry`（不对称比）—— 我建议用它替代"能不能买"

用户问"还有没有买入机会"，我更愿意把它翻译成一个可计算的量：

> **不是问"能不能买"，而是问：如果结构性成立我赚多少；如果证伪我亏多少。**

```
asymmetry = 上行空间 / 下行空间
          = (PE_structural_mid − PE_now) / (PE_now − PE_cyclical_mid)
```

- `> 2`：赔率合适，值得下手
- `1 ~ 2`：鸡肋
- `< 1`：赢了赚一点、输了亏很多 → **直接否掉**

> ❗**`PE_now ≤ PE_cyclical_mid` 时分母 ≤ 0**：必须返回 `None` 并标注「已跌破周期带，需人工判断（可能是价值陷阱）」。
> **绝不能返回 `inf` 或 `999`** —— 那会让"最危险的票"排在最前面。

### 2.3 核心新增指标三：`entry_window` —— 状态机 × 定价进度 的九宫格

把已有的 S0–S4 状态机（`valuation_state.py`，现在只管基本面、**完全没接价格**）与 `priced_in_ratio` 交叉成 3×3：

|  | priced_in < 0.3 | 0.3 ~ 0.7 | > 0.7 |
|---|---|---|---|
| **S0/S1**（早期） | ★ 最佳赔率区：基本面刚起、市场没定价；胜率最差，仓位要小 | 正常建仓区 | 故事先行、基本面没跟上 → 警惕 |
| **S2**（瓶颈验证） | 认知差窗口 | ★ 平衡点：有证据、未充分定价 | 需要业绩加速兑现才安全 |
| **S3/S4**（利润兑现） | 少见的错杀，重点核查数据 | 趋势跟随，别当重估 | ⚠ **业绩兑现即出货区**：利润已兑现且已定价 |

> ❗九宫格**每格都必须有文案**，不许留空白格 —— 空白格在 UI 上就是黑屏，是"合法的空"。

## 5. 风险与取舍

- **东财美股覆盖不全**（这是真实风险，不是假设）。方案里已要求：取不到必须 `None` + 原因，UI 如实呈现，不接受"用行业均值补"。
- **自算 PE 序列依赖日 K + EPS 口径**，A 股累计口径/美股单季口径必须分开处理（见 §1.1 的 ⚠️）。
- **`asymmetry` 是估值维度，不是放行信号**。它和 `panic_probe` 一样 —— **只进门理由，不参与闸门**，禁止拿它去放松 Manas 阈值。
- 不改 `TransitionRules` 的阈值语义，只增加价格侧的派生字段，状态机本身保持纯基本面。
