# 做 T 降成本模块设计（长期持有 + 日内回转）

> 实现：`deva/naja/bandit/{core_position,intraday_deviation,t_rotation}.py`
> 守卫：`scripts/verify/verify_t_rotation_core.py`（25 项，`ALL PASS` 且通过负向验证）

## 一、需求与拆解

原始需求：

> 「如果持仓里面有的话，咱们就把持仓里面的做 T 去降低成本嘛。
> 　我们其实还要长期持有一个半导体指数（AI 时代长期价值投资）。
> 　不过中间可以做 T，但要利用这种流动性的机会，**做完之后一定要买回来，保证我们长期持有**。」

拆成三条交付物，以及一条不可协商的约束：

| # | 需求 | 落地位置 |
|---|---|---|
| 1 | 持仓里的票做 T 降成本 | `TRotationEngine.on_tick()` 驱动正 T / 倒 T |
| 2 | 长期持有半导体/芯片指数作为底仓 | `CorePositionLedger.set_plan()` 登记目标份额 |
| 3 | 做完必须买回 | ★ 份额守恒铁律 + 回购义务账本 |

### ★ 份额守恒铁律

**任何一轮做 T 结束时，约定持有份额不得低于开始时。**

口径：

```
effective_shares = 真实 OPEN 持仓 + 未履行回购义务
```

四步走一圈，这个量始终不变：

| 阶段 | 真实持仓 | 回购义务 | effective |
|---|---|---|---|
| 起始 | 10000 | 0 | 10000 |
| 倒 T 卖出 2000 | 8000 | 2000 | **10000** |
| 倒 T 买回 2000 | 10000 | 0 | **10000** |
| 正 T 买入 2000 | 12000 | 0 | **12000** |
| 正 T 卖出 2000 | 10000 | 0 | **10000** |

每个轮次收尾都真刀真枪校验一次（`_verify_conservation`），违反即 `log.error` 暴露。
守卫第 23 项用 AST 静态锁死：任何 `_close_*` 路径都必须调用它——**漏一条就是静默失效**。

收益口径用 `realized_edge` 而不是"盈亏"：做 T 的收益本质是**冲抵底仓持有成本**，
抬高成本的情况必须能显现为负数。

## 二、为什么两种打法都依赖底仓

这是 A 股 T+1 的直接后果，也正是用户那句"仓位是 0 你就没办法做 T"的本质：

- **正 T（先买后卖）**：低点买 N 份 → 卖出**更早持有**的 N 份。
  当日买入当日不可卖，所以必须先有"昨天的票"。
- **倒 T（先卖后买）**：卖的就是底仓。

**两者都要求持仓不为 0。** 空仓时连做的资格都没有，遇到振幅 6% 的日子只能干看着——
这就是**底仓存在的理由：它不是用来炒的筹码，是"随时能做 T 的权利"（一份期权）**。

因此 `target_shares` 以内的份额**永不参与卖出**。

## 三、判据：为什么锚必须是「昨收」而不是 VWAP

> 这一节记录的是一个真踩过的坑，改动前请务必读完。

第一版拿 VWAP 当主锚，跑 2026-10-13 科创芯片的真实行情，结果 **0 次触发**。
逐层拆闸门发现是两个**独立**缺陷叠加，别混为一谈：

### 缺陷一：VWAP 会跟着价格漂移（实测低估 7.4 倍）

```
price=3208 时：相对昨收 -4.25%，相对 VWAP 只有 -0.57%
```

低开低走的日子里 VWAP 一路跟着价格下移，于是"相对成交重心的偏离"始终很小——
明明已经跌了 4%，指标却说"挺接近重心"。

**用一个跟着被测对象跑的指标做均值回归的锚，本身就是错的。**

落到净空间上差距更致命：`0.42%` vs `1.98%`，前者几乎擦着 0.35% 的门槛过不去。

### 缺陷二：趋势保护用错了尺度（这才是那次 0 次触发的直接原因）

当时写的是"连续 N 根（默认 6）阴线就不低吸"。可在分钟级分时上，
**任何一段像样的下跌都是几十根连续阴线**，等于永久禁止低吸。

正确做法是反过来：**要求连跌已被打断**（`require_stabilize`，见下），
即"我已经不再下跌了"，而不是"我跌得太久所以不许买"。

### 修正后的判据

主锚 = **昨收**（完全外生，且直接对应本策略核心场景：隔夜外盘冲击 → 今日低开 → 向昨收回归）。
VWAP 降级为**方向确认**与**了结参考**。

保守起见，预期空间不假设走满全程：`|ret| × reversion_ratio`（默认只算回归一半）。

## 四、闸门清单

### 触发（六道，全部可人肉复算）

1. `samples >= min_samples` — VWAP 预热
2. `amplitude >= min_amplitude` — 死水行情不动手
3. `|ret|` 到达阈值 — 主判据，锚是昨收
4. **右侧确认**：低吸要求连跌已被打断，高抛要求连涨已被打断
   （不等极值，等转折。省下的那点收益远不及接飞刀/卖飞的代价）
5. `|ret| <= max_dev_close` — 极端偏离多半是基本面事件，均值回归假设失效
6. `|ret| × reversion_ratio − 往返成本 >= min_net_edge` — 空间撑不起成本就别做

### 摩擦成本（最容易忽略、也最致命的一环）

```
round_trip_cost = 2 × (commission + slippage) + stamp_duty
```

场内 ETF 免印花税： `2 × (0.025% + 0.05%) = 0.15%`。
**若标的是个股，`stamp_duty_pct` 必须改成 0.05。**

空间小于成本时做 T 不是在降成本，是在给券商打工。

### 了结：跟踪回撤，不是固定目标

开仓严格，**了结用跟踪回撤**（`close_drawdown_pct`）：一直涨就一直拿，
从最高点回撤够了才走。

实测差异（同一天行情）：

| 了结方式 | 买点 | 卖点 | 收益 |
|---|---|---|---|
| 回到 VWAP 就走 | 3208.92 | 3226.06 | **+0.53%** |
| 跟踪回撤 0.3% | 3208.92 | 3391.92 | **+5.70%** |

倒 T 镜像：`buyback_rebound_pct`，价格从卖出后最低点反弹够了才买回（确认跌不动）。

## 五、绕过的三个坑（都已被守卫锁死）

### 坑 1：止盈止损会把做 T 的腿半路强平

`VirtualPortfolio.update_price()` 会在触发止盈止损时自动平仓。
做 T 的腿若被半路平掉，整个轮次闭环失败、份额流失，而且**不报错**。

→ 两条腿一律 `stop_loss_pct=-95.0, take_profit_pct=995.0` 推到不可达。（守卫 22）

### 坑 2：回购义务可能被仓位限额拒绝

买回是**必须完成**的任务。若因撞到 `max_total_pct` 而买不回来，
就等于侵蚀了长期持有的底仓——这比超限本身严重得多。

→ `open_position(bypass_limits=True)`，**仅供回购义务使用**，日常开仓必须 False。
引擎会打 `warning` 留痕。（守卫 21）

### 坑 3：已履行的回购义务会被重复计入

`open_obligation` 是纯记账动作，**可以被单独调用而不伴随减仓**。
若如此，`carried_in` 会凭空多出一份，卖出额度跟着虚增。

→ 账本保持纯粹（不自证），由静态守卫约束调用方：任何调 `open_obligation`
的地方，同一个方法体内必须有 `_reduce_symbol` / `reduce_position`。（守卫 25）

## 六、参数建议（半导体/芯片指数 ETF）

```python
RotationThresholds(
    commission_pct=0.025,      # 单边佣金（万2.5）
    slippage_pct=0.05,         # 单边滑点
    stamp_duty_pct=0.0,        # ⚠️ ETF 才为 0；个股改成 0.05
    buy_dev_close=1.5,         # 相对昨收跌 1.5% 才考虑低吸
    sell_dev_close=1.5,
    reversion_ratio=0.5,       # 保守：只假设回归一半
    min_amplitude=1.0,
    min_net_edge=0.35,
    max_dev_close=8.0,
)

TRotationConfig(
    max_round_pct=0.30,        # 单次最多动用可轮换份额的 30%
    cash_reserve_pct=0.20,     # 正 T 需留备用资金
    round_lot=100.0,           # ETF 100 份起
    close_drawdown_pct=0.3,
    buyback_rebound_pct=0.3,
)
```

**波动性排序**（选标的时权衡振幅与安全性）：

```
上证50（太钝，银行权重高）< 沪深300 < 中证500/1000 < 行业指数（如科创芯片）
```

今天的实测：科创芯片振幅 5.85%，低吸高抛空间约 6.11%——但这种锐度伴随着同等的风险。
