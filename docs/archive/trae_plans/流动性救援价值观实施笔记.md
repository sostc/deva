# 流动性救援价值观实施笔记

## 项目概述

**目标**: 在市场恐慌、流动性枯竭时提供流动性支持，等待市场恢复后获利

**时间**: 2026-03-28

**用户核心价值观**:
> 在别人恐慌、急需用钱时提供流动性，相信市场会自我修复，等恢复正常时卖出获利

### ✅ 步骤3: 实现恐慌指数计算
**文件**: `deva/naja/attention/filters/panic_analyzer.py`

**计算公式**:
```
panic_score = (
    price_destabilization × 0.25 +
    volume_shrink × 0.25 +
    spread_expansion × 0.20 +
    fear_sentiment × 0.20 +
    event_severity × 0.10
) × 100
```

**恐慌等级分类**:
| 等级 | 恐慌指数 | 流动性得分 | 说明 |
|-----|---------|-----------|------|
| extreme | ≥80 | <0.15 | 极端恐慌 |
| high | ≥70 | <0.25 | 高恐慌 |
| elevated | ≥50 | <0.4 | 恐慌升高 |
| moderate | ≥30 | - | 中度恐慌 |
| low | <30 | - | 低恐慌 |

**关键方法**:
- `is_panic_peak()`: 检测恐慌极点
- `get_panic_trend()`: 获取恐慌趋势

**验证结果**: ✅ 通过

### ✅ 步骤4: 扩展 ValueSystem 支持 liquidity_rescue
**文件**: `deva/naja/attention/values/system.py`

**新增的对齐度计算**:
```python
elif active_type == "liquidity_rescue":
    panic_score = features.get("panic_level", 0) / 100.0
    liquidity_score = features.get("liquidity_score", 0.5)
    recovery_signal = features.get("recovery_signal", 0)

    liquidity_crisis_score = 1.0 - liquidity_score

    alignment = (
        panic_score * 0.35 +
        liquidity_crisis_score * 0.35 +
        recovery_signal * 0.30
    )

    alignment *= weights.liquidity_weight
    return min(1.0, alignment)
```

**验证结果**: ✅ 通过

### ✅ 步骤5-7: 实现三个核心策略
**文件**: `deva/naja/attention/strategies/liquidity_rescue_strategies.py`

#### 7.1 PanicPeakDetector - 恐慌极点检测器
**功能**: 检测恐慌极点（卖压衰竭点）

**检测条件**:
1. 当前恐慌指数处于局部最高点
2. 成交量开始恢复（萎缩减缓）
3. 价格下跌速度开始放缓

**信号类型**:
- `PANIC_PEAK_DETECTED`: 恐慌极点确认
- `RESCUE_OPPORTUNITY`: 救援机会出现

#### 7.2 LiquidityCrisisTracker - 流动性危机追踪器
**功能**: 持续追踪流动性状态

**危机等级计算**:
```
crisis_level = (
    spread_crisis × 0.4 +
    volume_crisis × 0.3 +
    depth_crisis × 0.2 +
    bid_ask_imbalance × 0.1
)
```

**信号类型**:
- `LIQUIDITY_CRISIS_CONFIRMED`: 流动性危机确认
- `LIQUIDITY_CRISIS_WARNING`: 流动性预警

#### 7.3 RecoveryConfirmationMonitor - 恢复确认监测器
**功能**: 监测市场是否开始恢复

**恢复评分**:
```
recovery_score = (
    price_score × 0.4 +
    volume_score × 0.3 +
    spread_score × 0.2 +
    sentiment_score × 0.1
)
```

**信号类型**:
- `RECOVERY_CONFIRMED`: 恢复确认
- `RECOVERY_STARTED`: 恢复开始
- `EXIT_OPPORTUNITY`: 退出机会

#### 7.4 LiquidityRescueOrchestrator - 协调器
整合三个策略，统一输出救援决策

**状态等级**: normal → warning → opportunity → peak → crisis → recovery

**验证结果**: ✅ 通过

## 问题与解决

### 问题1: 导入循环依赖
**现象**: 某些模块在导入时出现循环依赖错误

**解决**: 使用延迟加载（lazy import），在方法内部导入而非模块顶部

### 问题2: 事件 features 字段可能缺失
**现象**: 某些事件可能没有预计算的 panic_level 等字段

**解决**: 使用 `features.get("field", default)` 提供默认值

### 问题3: 恐慌极点检测需要足够历史数据
**现象**: 初始阶段 history 不够导致检测不准确

**解决**: 添加 `if len(self._panic_history) < 5: return` 等待数据积累
