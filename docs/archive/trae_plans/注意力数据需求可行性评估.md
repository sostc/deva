# 需求可行性评估报告

## 需求概述
1. 将 RealtimeDataFetcher 接入数据源管理体系
2. RealtimeDataFetcher 实现 DataSource 接口或包装层
3. 在数据源管理面板显示注意力数据获取状态
4. 暴露注意力数据获取的统计信息（获取次数、错误率、档位分布）

---

## 一、现有代码分析

### 1.1 RealtimeDataFetcher (attention/realtime_data_fetcher.py)
- **定位**：注意力系统内置的实盘数据获取器，独立于数据源系统
- **数据获取**：直接从 Sina 行情源获取，不依赖数据源系统
- **运行模式**：只在交易时间运行，订阅交易时钟信号
- **已有统计** (`get_stats()`)：
  - `running`, `active` - 运行状态
  - `fetch_count`, `error_count`, `last_error` - 获取统计
  - `high_count`, `medium_count`, `low_count` - 档位分布 ✅
  - `current_phase`, `is_trading` - 交易时间状态
- **全局单例**：`get_data_fetcher()`, `set_data_fetcher()`

### 1.2 DataSourceEntry (datasource/__init__.py)
- 继承自 `RecoverableUnit`
- 完整生命周期管理：start(), stop(), is_running
- 状态持久化：status, error_count, last_error, last_data_ts, total_emitted
- 代码编译和执行能力

### 1.3 DataSourceManager (datasource/__init__.py)
- 单例模式，统一管理所有数据源
- CRUD 操作：create(), get(), list_all(), start(), stop(), delete()
- 统计接口：get_stats()

### 1.4 数据源管理 UI (datasource/ui.py)
- 统计卡片展示：总数据源、运行中、已停止、错误数
- 类别 Tab 展示：产业链分层、概念板块、市场分类等

## 二、需求可行性评估

### 需求 9: 将 RealtimeDataFetcher 接入数据源管理体系

**可行性：✅ 可靠，但需要设计决策**

**方案 A：作为特殊数据源类型注册**
```
DataSourceManager.register_special_datasource("attention_realtime", fetcher_instance)
```
- 优点：完全复用现有管理机制（启动/停止/持久化/UI展示）
- 缺点：RealtimeDataFetcher 已经依赖 attention_system，生命周期可能冲突

**方案 B：在 DataSourceManager 中添加旁路支持**
```python
class DataSourceManager:
    def get_attention_fetcher_stats(self) -> dict:
        fetcher = get_data_fetcher()
        return fetcher.get_stats() if fetcher else None
```
- 优点：保持 RealtimeDataFetcher 独立运行，仅暴露状态
- 缺点：不是真正的"接入"，只是状态同步

**推荐**：方案 B 更稳妥，避免侵入性改造

---

### 需求 10: RealtimeDataFetcher 实现 DataSource 接口或包装层

**可行性：⚠️ 复杂度较高，设计决策关键**

**挑战**：
1. DataSourceEntry 期望 `fetch_data()` 函数返回数据，但 RealtimeDataFetcher 是持续运行的循环
2. DataSourceEntry 有代码编译机制，RealtimeDataFetcher 没有
3. 两者生命周期管理逻辑不同（交易时间 vs 全天候）

**可行方案**：
```python
class AttentionDataSourceWrapper(DataSourceEntry):
    """包装 RealtimeDataFetcher 为标准数据源"""

    def __init__(self, attention_system):
        metadata = DataSourceMetadata(
            name="注意力实时行情",
            source_type="attention_realtime"
        )
        super().__init__(metadata)
        self._fetcher = RealtimeDataFetcher(attention_system)

    def fetch_data(self):
        """不符合 DataSourceEntry 范式"""
        raise NotImplementedError("使用旁路获取数据，不走标准 fetch_data")
```

**结论**：强行适配反而破坏现有设计，建议通过方案 B 的旁路方式暴露状态

### 需求 11: 在数据源管理面板显示注意力数据获取状态

**可行性：✅ 简单可靠**

**实现方式**：
在 `ui.py` 的 `_render_stats_html()` 中添加新的统计卡片：
```python
def _render_stats_html(stats: dict, attention_stats: dict = None) -> str:
    cards = [
        {"label": "总数据源", "value": stats["total"], ...},
        {"label": "运行中", "value": stats["running"], ...},
        ...
    ]

    if attention_stats:
        cards.append({
            "label": "注意力获取",
            "value": "运行中" if attention_stats.get('active') else "已停止",
            "gradient": "...",
        })
        cards.append({
            "label": "获取次数",
            "value": attention_stats.get('fetch_count', 0),
        })

    return render_stats_cards(cards)
```

**工作量**：小，约 20-30 行代码

---

### 需求 12: 暴露注意力数据获取的统计信息

**可行性：✅ 已经实现，只需暴露**

**现状**：
- `RealtimeDataFetcher.get_stats()` 已返回完整统计
- 包括：获取次数、错误率、档位分布

**实现方式**：
在 `DataSourceManager` 添加方法：
```python
def get_attention_stats(self) -> dict:
    fetcher = get_data_fetcher()
    if fetcher:
        return fetcher.get_stats()
    return None
```

或在 `get_stats()` 中合并：
```python
def get_stats(self) -> dict:
    base_stats = {...}  # 现有统计
    fetcher = get_data_fetcher()
    if fetcher:
        base_stats['attention'] = fetcher.get_stats()
    return base_stats
```

## 三、综合评估结论

| 需求 | 可行性 | 复杂度 | 推荐方案 |
|------|--------|--------|----------|
| 9. 接入数据源管理体系 | ✅ 可靠 | 中 | 旁路暴露状态，非侵入式接入 |
| 10. 实现 DataSource 接口 | ⚠️ 复杂 | 高 | 不推荐，收益小于成本 |
| 11. UI 显示获取状态 | ✅ 简单 | 低 | 在现有 UI 中添加统计卡片 |
| 12. 暴露统计信息 | ✅ 已实现 | 低 | 添加暴露接口即可 |

## 五、风险与注意事项

1. **注意类型**：注意力系统和数据源系统是松耦合的，不应强行耦合
2. **性能考虑**：获取注意力统计不应阻塞 UI 渲染
3. **向后兼容**：现有数据源管理功能不应被破坏
